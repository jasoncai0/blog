# 批注楼层与 AI 回复 — 设计

日期：2026-11-12　状态：已实施

## 要解决的问题

现在的批注是一条「原文 + 一段文字」，`thread` 数组里只有第一条是人写的，其余只读渲染，没有楼层概念；写接口全公开，谁都能改。目标是：你在文章里划一句、写一条疑问，之后（人或 AI）能在同一条批注下回复，形成楼层。

## 决定

1. **楼层**：一条批注的 `thread` 就是一个楼层数组，`thread[0]` 是发起人（你），`thread[1..]` 是回复，界面显示「1 楼 / 2 楼 …」。上限 50 层。
2. **署名**：人写的一律 `author: "我"`；AI 回复写 `author: "AI"`，界面上用不同颜色和左边线区分。
3. **写入要口令**：读公开，写（新增/编辑/删除/回复）需要一个口令，放在 `X-Edit-Key` 请求头。口令存在服务端 `NOTES_EDIT_KEY`，浏览器第一次写时弹一次输入框，存本地 `jasoncai:notes:key`。
4. **回复是原子追加**：新增 `POST /api/notes/<slug>/<id>/replies`，服务端把这条 append 到 `thread` 末尾并返回整条笔记。避免「两台设备各拿旧副本整条 PUT」互相覆盖。
5. **AI 怎么回**：这一版不做自动服务。你把批注发出去，在对话里说一声，我用同一个接口以 `author: "AI"` 追加回复。以后要做自动扫描再单开。

## 接口

```
POST /api/notes/<slug>/<id>/replies
  X-Edit-Key: <key>
  {"author": "AI", "text": "...", "t": 1794...}
  200 -> {"ok": true, "note": {...}}
  404 -> 笔记不存在或已删除
  409 -> 楼层已满
```

## 前端

- 气泡里：顶部「1 楼 我 · 12:09」+ 可编辑的原文（你写的那条），下面按楼层列出回复，底部是「回复」输入框 + 按钮。
- 401 时弹口令框，存本地后重试；队列里的操作在没口令时暂停，输入后自动补发。
- 首页/侧栏计数不变（按笔记条数，不按楼层）。

## 不做

- 不做楼中楼（回复的回复还是一条平铺楼层）。
- 不做实时推送（刷新/重新打开才看到新回复）。
- 不做 AI 自动回答的调度。
