怎么读这张图

两个面板共享同一个窗口 W：DSH 的阈值是 min(0.8W, W−O−65,536)，OpenCode 的阈值是 W−max(0.15W, 16k)。把 W 调到 20 万，DSH 会在约 12.6 万就压缩，OpenCode 等到 17 万；DSH 压完保留约 3 万，OpenCode 只留 1.5 万。

“累计输入”把每次请求的 system + tools + history 相加。它说明上下文预算同时是成本预算：压缩越早，后续每一步重复发送的 token 越少。DSH 的 Loop 不会因为 step 数停下，OpenCode 会在第 steps 步强制文本回复。

把“单步输出”拉到输出上限以上：DSH 以 max-tokens 结束 turn；OpenCode 会续写，连续三次 finish:"length" 才抛 output-limit 错误。

简化模型

# DSH · compaction-basic
T = min(0.8·W, W − O − 65,536)
R = 0.16·(W − O)
# OpenCode · session/compaction
C = W − max(0.15·W, 16,000)
K = 15,000
# 每步请求
input = 12,000 + history

真实实现里 system/tools/history 的计量、压缩范围选择和 provider 缓存都更细；这里只保留决定“谁先触发”的主项。DSH 的 O 取请求头的 maxTokens 或 adapter 默认值。
