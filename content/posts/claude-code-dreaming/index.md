> 机制部分来自 Claude Code 2.1.321 二进制里的提示词和调度代码，可以直接 `strings` 核对。效果数据来自 Anthropic 2026-11-06 的研究博客和 Dreams 文档。逆向得到的默认值我会标明来源；官方文档没写的，不等于没有。

2026 年 11 月，Anthropic 在《The components of agent memory》里讲了一个宝可梦的失败案例。Claude 在月见山入口把宝可梦中心记成了「在东侧」，走出门就宣布「月见山已经在身后」，然后朝错误方向走，掉下单向台阶三次，最后写了一句「我打算停下，不再循环」。

错误不在推理，在记忆。它把一句当时看起来合理的判断写进笔记，之后每个会话都拿这句当事实。dream 做的事很窄：把这条笔记和会话 transcript 对上，发现方向错了，改掉。改完之后，Claude 用 1,935 步走到了华蓝市。

这个案例说明了 dream 的定位。它不负责让模型变聪明，也不负责压缩上下文。它负责让记忆别烂掉。

## 一、在线写记忆，缺的是什么

模型有三种获得知识的方式：改权重、在上下文里学、把东西写到外部存储。dream 只跟第三种有关。

Claude Code 的 auto memory 默认开启。每次回复结束，它有机会把值得记的东西写进 `~/.claude/projects/<project>/memory/`。这条路很快，写完了下一轮就能读到。问题也在这里。

**只看得见当前会话。** 同一个构建错误在五个会话里各出现一次，每个会话都只知道自己这一次。没有哪个会话有位置说「这是第三次了，根因在缓存目录」。

**写的时候没有对照物。** 模型凭当下的判断决定记什么，判断错了也发现不了。月见山的笔记就是这么来的：它当时真的相信宝可梦中心在东侧。

**和主任务抢注意力。** 整理记忆要读文件、合并、改索引，做得越细，越容易打断正在做的事。Sonnet 3.7 在宝可梦里的表现是个极端例子：10,000 步时写了 413 个文件、225 个文件夹、977,930 个字符，只拿到 1 个徽章。它花了大量步数在维护记忆，而不是玩游戏。

dream 把维护挪到后台。它读 transcript，拿到「当时到底发生了什么」；读现有记忆，拿到「现在相信什么」；然后逐条对照。产出是改写、删除、合并、提升，不是摘要。摘要只压缩，不改错；对账要拿证据改错。

代价是异步。dream 跑完之前，新记忆不会生效；跑一次也要花 token。这套机制只在「记忆会跨很多会话复用」时才划算。

## 二、记忆分四层，dream 在层与层之间搬东西

Anthropic 把 agent 记忆分成四层。层与层之间不是替代关系，是成本与精度的取舍。

{{< fig "diagrams/01-memory-hierarchy.svg" "记忆的四个层级。越往上越小、越贵、每次会话都要加载；越往下越大、越便宜、按需检索。dream 的箭头表示它可以在任意两层之间读写。" >}}

最底下是 **transcripts**。每个会话一个 JSONL 文件，只追加，记录用户说了什么、模型调了什么工具、工具返回了什么。它是事实源，但只是「当时看到的事实」，不是世界真相。

往上是 **memory notes**。Claude 自己写的主题文件，带 `user`、`feedback`、`project`、`reference` 四类标签，写入时记一个 ISO 时间戳。官方文档明确说，代码库里能推导出来的东西、CLAUDE.md 已经写过的内容，不要重复存。

再往上是 **memory representations**，最典型的是 wiki：一页一个主题，页与页之间有链接。它不存原始事实，存的是「怎么找到事实」的地图。Anthropic 的 Stainless 实验里，wiki 从 2 个会话后的 103 页、766 条链接，长到 128 个会话后的 222 页、12,893 条链接。

最顶上是被注入的上下文。Claude Code 不把整个记忆目录塞进每次会话，只加载 `MEMORY.md` 的前 200 行或 25KB。这个文件是索引，不是内容仓库。一条索引长这样：

```markdown
- [Build cache gotcha](build-cache.md) — turbo 缓存不认环境变量，改完要 --force
```

越往上越贵。注入层每个会话都要付一次 token，所以它必须小，而且必须准。越往下越便宜，但要用的时候得先知道去哪找。dream 的工作，一半是往上搬（把重要的提升成索引或 wiki 页），一半是往下压（把细节从索引挪回主题文件）。

主题文件和 wiki 页的分工，可以用一条构建踩坑说明。报错原文、触发条件、可用命令写进 `build-cache.md`；当这条踩坑同时影响 CI 缓存和本地增量构建、需要一条入口把几个主题串起来时，才在 wiki 里建一页，写「什么时候会遇到、先看哪几篇」，不复制命令。wiki 是入口，主题文件是内容。同一条知识如果两边都写全，就是重复，下一次 dream 还要花时间合并。

## 三、什么时候会做梦：六道检查

Auto Dream 的入口在每次回复结束后的 stop hook 里。只有主代理会触发，子代理不触发。调用方式是 fire-and-forget，不阻塞回复：

```ts
void executeAutoDream(stopHookContext, toolUseContext.appendSystemMessage)
```

真正开跑之前要过六道检查，按开销从低到高排：

| 顺序 | 检查 | 2.1.321 里的值 | 开销 |
| --- | --- | --- | --- |
| 1 | 功能开关 | GrowthBook `tengu_onyx_plover`，可被 settings 的 `autoDreamEnabled` 覆盖 | 读内存 |
| 2 | 时间 | 距上次整合 ≥ 24 小时 | 一次 stat |
| 3 | 扫描节流 | 上次扫描后至少 10 分钟 | 时间戳比较 |
| 4 | 会话数 | 至少 5 个新会话，排除当前会话 | 扫目录 |
| 5 | 写权限 | 当前权限规则不能拒绝记忆写入 | 读配置 |
| 6 | 锁 | 没有别的进程正在整合 | stat + 读文件 |

会话数的基准是上次整合的时间，不是上次扫描的时间；列表里会剔除当前会话。`listSessionsTouchedSince(last)` 的 `last` 就是那个 mtime。范围跟着记忆目录所在的 project 走，跨项目的模式不会被一次 dream 看到。

前五道在 `autoDream.ts` 里，第六道在 `consolidationLock.ts` 里。社区在 2026 年 4 月的逆向文档里列的是五道，2.1.321 多了第 5 道权限检查：如果当前会话的权限规则会让 dream 写不了记忆，干脆不启动，免得跑一半被拒。

{{< fig "diagrams/02-gates.svg" "一次 dream 的六道检查和四个阶段。任一道不通过就退出；只有会话、权限、锁失败才记 skip 事件，时间与节流只留日志。" >}}

为什么是 24 小时加 5 个会话，而不是每轮都跑？两个原因。dream 一次要读多个会话，会话太少，跨会话的模式还没出现，跑了也只能重复整理已有笔记；跑一次要付整个子代理的 token，频率太高，成本会超过它省下的重复劳动。

扫描节流是给时间检查擦屁股的。时间够了但会话不够时，锁文件的 mtime 不会更新，下一轮时间检查又会通过。如果不节流，每个 turn 都会扫一次会话目录。10 分钟是这段代码里的常量 `ce = 600000`。

不是所有不通过都会记事件。时间不够、节流没过，代码直接 return，只留日志；会话不够、权限拒绝、抢锁失败会记 `tengu_auto_dream_skipped`，`reason` 是 `sessions`、`permission_rule`、`lock`。抢到锁之后还有两个分支：记忆条目读不出来（`items_unreadable`），或者条目记录比本次整合更新（`record_newer`），也会 skip 并还锁。跑起来记 `tengu_auto_dream_fired`，完成记 `tengu_auto_dream_completed`，失败记 `tengu_auto_dream_failed`。后台任务不等于黑盒，只是大多数人不去看事件。

## 四、梦里做什么：四个阶段

2.1.321 里的提示词标题是 `# Dream: Memory Consolidation`，第一句是：

> You are performing a dream — a reflective pass over your memory files.

提示词把工作拆成四段。

**Phase 1，定向。** `ls` 记忆目录，读 `MEMORY.md` 索引，浏览已有主题文件，避免创建近似重复的文件。如果有 `sessions/` 子目录，看一眼最近的条目。

**Phase 2，收集近期信号。** 优先级只有两条。第一条是「和当前代码库矛盾的旧记忆」，也就是漂移。第二条才是 grep transcript。提示词专门写了：transcript 是大 JSONL 文件，窄查询，不要整读。

```bash
grep -rn "<narrow term>" <transcripts>/ --include="*.jsonl" | tail -50
```

这个顺序值得注意。dream 先看「现在相信的东西哪里跟现实对不上」，再去找证据，而不是从 transcript 里重新总结一遍。前者是查错，后者是摘要。

**Phase 3，整合。** 新信号合并进已有主题文件，不创建近似重复的文件。相对日期转成绝对日期，「昨天」要写成具体哪一天，不然过两周就不可解读。被推翻的事实直接删，不留在文件里当历史。

**Phase 4，修剪和索引。** 更新 `MEMORY.md`，保持在 200 行、约 25KB 以内。每条索引一行，约 150 个字符以内，格式是 `- [Title](file.md) — one-line hook`。超过 200 字符的索引行说明内容放错了层，要挪回主题文件。删除失效指针，解决两个文件之间的矛盾。

2.1.321 的提示词里还有两个额外的块，比早期逆向文档更新。

一个是**团队记忆**。`team/` 子目录放全仓库共享的记忆，别人的 Claude 会话也会写。规则很保守：可以删被代码明确推翻的团队记忆，但不能因为「我不认识它」或「它跟我最近的会话无关」就删。个人记忆跟团队记忆重复时，删个人的。dream 不允许把个人记忆提升进 `team/`，那是用户显式执行 `/remember` 时才做的决定。

另一个是**和 CLAUDE.md 对账**。这两者都算「项目约定」，冲突时听谁的，提示词给了三条规则：

- 记忆过时：CLAUDE.md 是维护过的、签入仓库的版本。删记忆，或者改写它，保留「为什么」但改掉「怎么做」。
- CLAUDE.md 过时：记忆有明确更晚的日期，并且明确纠正了 CLAUDE.md。dream 不许改 CLAUDE.md，只能在记忆里标「contradicts CLAUDE.md — verify which is current」，然后写进总结让用户处理。
- 不算冲突：记忆补充了 CLAUDE.md 没覆盖的细节，或者带理由地收窄了某条规则。留着。

最后一段要求返回简短总结：整合了什么、更新了什么、删了什么。如果记忆已经很紧，没有变化，就直说没有变化。

## 五、怎么保证不越权：fork、只读、锁

dream 不是在主会话里加一段提示词，而是 fork 一个子代理。任务类型是 `dream`，`querySource` 是 `auto_dream`，`forkLabel` 也是 `auto_dream`，`skipTranscript: true`。最后这个标记很重要：dream 自己不写 transcript，否则每次做梦都会产生新会话，下一次做梦又会去读它，形成自我循环。

工具权限收得很紧。读文件、Grep、Glob 不限；Edit 和 Write 只能落在 auto memory 目录里；Bash 只允许只读命令（`ls`、`find`、`grep`、`cat`、`stat`、`wc`、`head`、`tail` 这一类），外加一个例外：可以删记忆目录里的 `.md` 文件，`rm` 只允许带 `-f`，且不能碰 `.git`、`agents` 这类受保护子目录。MCP、Agent、其他写操作一律拒绝。

锁是一个 `.consolidate-lock` 文件。内容是持有者的 PID，mtime 是上次整合时间，超过 1 小时视为过期，防止 PID 复用导致死锁。两个进程同时抢，最后写入者获胜，失败者在重新读取时退出。整合失败会把 mtime 回退到获取前的值，下一次尝试不用等满 24 小时。

这个回退有个副作用：24 小时门控下一轮又会通过。代码里没看到指数退避，同一进程内，实际重试间隔主要靠 10 分钟扫描节流兜底。一次持续失败，最坏大约每 10 分钟烧一个子代理；值不值得加告警，看你多在意这个成本。用户按 `x` 中止时，也会走回退。

{{< fig "diagrams/03-sequence.svg" "一次 dream 的时序。主会话在 stop hook 里发起，runner 过检查、抢锁、fork 子代理；子代理读记忆和 transcript，写回文件；结束后发通知并释放锁。右侧是另一个进程抢锁失败的路径。" >}}

运行时状态栏显示 `dreaming`。可以打开详情，看到正在回顾几个会话、当前阶段是 `starting` 还是 `updating`、碰过哪些文件，也能中止。完成后如果有文件被改，主会话里会出现一条 `Improved` 通知，带上文件数和路径。

{{< fig "diagrams/04-lifecycle.svg" "一条记忆的生命周期。写入后进入活跃状态；环境变化会让它漂移；dream 按证据决定修正、删除、提升为索引或降级为细节。没有证据的条目保持原样。" >}}

## 六、效果：哪些数字可信

Anthropic 公开了几组评测，都是内部评测，不是独立复现。先划一条边界：CL-Bench 测的是「有记忆目录」和「没记忆」的差别，实验里没有单独开关 dream。它能证明记忆循环有效，不能把涨分算到 dream 头上。dream 的独立证据在后面的宝可梦、wiki 和合同任务里，那些证据也有各自的混淆变量。

**CL-Bench 数据库任务。** 每道题开新会话，唯一跨会话的东西是一个共享记忆目录。六个月里测下来，记忆带来的提升和基线强弱有关：

| 模型 | 无记忆 | 有记忆 |
| --- | --- | --- |
| Opus 5.5 | 0.655 | 0.838 |
| Sonnet 5.5 | 0.644 | 0.833 |
| Opus 5 | 0.564 | 0.828 |
| Opus 4.7 | 0.383 | 0.700 |
| Sonnet 5 | 0.306 | 0.610 |
| Sonnet 4.6 | 0.330 | 0.364 |

Sonnet 4.6 几乎没吃到记忆的红利。原因不是记忆没用，是它不读：它经常不打开记忆目录，也不去验证自己关于「为什么答错」的猜想。在有记忆的前提下，后来提示它「答题前先读记忆，然后显式验证猜想」，分数从 0.364 提到 0.641。能力更强的模型会自己完成这个循环。

另一条反直觉的结论：给模型写死「只记录失败」的规则，记忆带来的增益反而变小。Opus 5 少 0.234，Opus 4.7 少 0.150（相对自由判断，不是相对无记忆）。让模型自己判断什么值得记，比替它定规则更有效。

这组数据说明记忆循环本身值钱，尤其对不会主动读记忆的弱模型。dream 在其中的角色是把笔记整理干净，但实验没有拆出它的单独贡献。

**宝可梦：dream 的独立证据。** 前面说过 Sonnet 3.7 的 413 个文件和 1 个徽章。Fable 5 只写了 9 个文件加一个 `global.md`，43,406 个字符，拿到 4 个徽章。差别不在写得多不多，在写什么。`global.md` 放当前目标、道馆计划、自己总结的规则；`locations/` 放路线；`gameplay/` 放打法。钱数、当前位置这种每回合都能从屏幕读到的东西，不存。

月见山的对照更直接。带着错误笔记的那次，Claude 三次掉回原来的路，最后放弃；dream 修正笔记后，1,935 步到达华蓝市；完全没有记忆的那次，从来没到过。

**Wiki。** Stainless 的语料约 350,000 个文件、420M token，25 道题。dream 从 2 个会话扩到 128 个会话，只用 wiki 答题的得分从 13% 涨到 48%。wiki 加搜索从 54% 涨到 61%，只用搜索是 53%。wiki 加搜索平均每题省约 20,000 个 token。wiki 的价值在导航，不在替代检索。

这条曲线同时改了 wiki 的规模和整理轮次，涨分里有多少来自覆盖度、多少来自组织质量，官方没有拆开。能确认的是，链接从 766 涨到 12,893 之后，wiki 没有因为膨胀而失效。

**什么时候没用。** Harvey 的法律 Agent Benchmark（LAB）里，多文档、需要判断和计算的任务，wiki 得分 87%，搜索 73%。但单文档就能查到答案的任务，wiki 没有明显收益。还有一个更尴尬的案例：某个任务的 wiki 长到 203KB，而原文只有 115KB，是原文的 1.77 倍。地图画得比疆域还大，抽象失败了。

**多 agent 写同一页会丢事实。** 合同任务里，几个 agent 同时往共享的 `provisions.md` 写，57 条评分事实只活下来 41 条，72%。改成每个合同一页、一个 agent 写、条款逐字引用之后，57 条全在。这个实验跟 dream 不直接相关，但它解释了为什么提示词反复强调「合并进已有主题文件」和「不要创建近似重复」：并发写入会互相覆盖。

## 七、什么场景值得让它做梦

判断标准只有两条：这条知识会不会在下一个会话里被重复推导？它会不会很快变化？

| 场景 | 适不适合 | 原因 |
| --- | --- | --- |
| 长期项目的构建、测试、踩坑 | 适合 | 跨会话反复用，写一次省很多次 |
| 用户纠正和偏好 | 适合 | `feedback` 类记忆，一次纠正长期生效 |
| 多会话研究、文档库 | 适合，但要配搜索 | wiki 当导航图，单独用只有 48% |
| 团队共享约定 | 适合，修剪要保守 | `team/` 目录，别人的记忆不能随便删 |
| 长周期 agent 的策略和规则 | 适合 | 存屏幕读不到的东西，比如「连败三次就换时机」 |
| 一次性任务 | 不适合 | 攒不到 5 个会话，dream 根本不触发 |
| 余额、位置、当前分支 | 不适合 | 下一轮就过期，还会污染注入层 |
| 必须立刻生效的纠正 | 不适合 | dream 是异步的，当场改 CLAUDE.md 或直接写 |
| 单文档检索 | 不适合 | wiki 没有收益，搜索更快 |
| 高频变化的环境 | 不适合 | 24 小时的节奏追不上，容易固化错误 |
| 敏感对话 | 谨慎 | dream 要读 transcript；Dreams API 不支持 ZDR/HIPAA |

这张表也能反过来用。如果你发现自己的记忆目录里全是「当前状态」，dream 跑得再勤也没用，因为它拿不到可复用的规则。

## 八、和 Managed Agents 的 Dreams API 是什么关系

Claude Code 里的 Auto Dream 是本地实现。Anthropic 还有一个产品化的 Dreams API，跑在 Managed Agents 上。

接口是异步 job。输入是一个 memory store 加 1 到 100 个 session transcript；输出是一个新的 memory store，输入 store 永远不被修改。状态是 `pending`、`running`、`completed`、`failed`、`canceled`，running 时可以用返回的 `session_id` 流式观察。`instructions` 只做高层综合指导，逐行规定「第 3 行改成什么」通常没用。计费按所选模型的标准 token 价，成本随会话数量和长度近似线性。支持 Fable 5.x、Opus 5.5/5/4.8/4.7、Sonnet 5.5/5/4.6。

两个实现的差别在写入策略。API 产出新 store，你可以先 diff 再决定要不要替换，适合做审核流程。Claude Code 在锁的保护下原地改，简单，但没有天然的 diff 环节，所以它用 `Improved` 通知和文件列表让你知道改了什么。

共同点是核心模型：都要有事实源，都要有可修改的记忆，都要有一次对照。少了任何一样，dream 就退化成总结。

## 九、局限

**transcript 不是世界真相。** 它只记录模型当时看到了什么。月见山的案例能修，是因为 transcript 里有「走出门、掉下台阶」这些证据。如果错误发生在感知阶段，transcript 会把错误一起记下来，dream 拿它当 ground truth，只会把错误确认一遍。

**显著性判断仍会错。** 官方说模型判断显著性的能力在变强，但没人知道未来会需要什么。写下的规则可能一开始就是错的，也可能环境变了之后才变错。dream 要花 compute，不可能对所有记忆做持续校验。

**注入层很贵。** 25KB 每个会话都要付一次。索引越长，模型越可能不遵守，官方文档自己也警告过长指令文件会降低依从性。dream 在顶层做的很多工作其实是「别让它变大」。

**后台不等于可观测。** 状态栏只有一个 `dreaming`，失败要看事件或通知。多数人不会注意到一次静默的失败。

**和 CLAUDE.md 的权威冲突是常态。** 2.1.321 专门写了一段对账规则，说明这不是边角案例。两个都叫「项目约定」的东西，需要明确的优先级，否则模型每次都要猜。

**研究预览。** Dreams API 不支持 ZDR 和 HIPAA。企业用之前要过数据治理，尤其是 transcript 里可能带客户数据。

## 十、怎么开，怎么看

auto memory 默认开启，目录在 `~/.claude/projects/<project>/memory/`。`MEMORY.md` 是索引，主题文件按需读。memory 文件不受 `cleanupPeriodDays` 清理。

设置里有两个开关：

```json
{
  "autoMemoryEnabled": true,
  "autoDreamEnabled": true
}
```

`autoDreamEnabled` 不设时，由 GrowthBook 的 `tengu_onyx_plover` 决定，这个 flag 还能远程改 `minHours` 和 `minSessions`。环境变量 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 可以整个关掉 auto memory。

`/memory` 对话框会显示 auto dream 的状态和开关，前提是当前账号和权限允许。任务栏出现 `dreaming` 时，可以打开详情看进度，也可以中止。

如果你要判断一次 dream 值不值，别只看「完成」。看三样东西：改了哪些文件、索引有没有变短、有没有把「当前状态」写进主题文件。三样里有两样不对，下次先把记忆目录清一遍，再让它跑。

dream 是一次需要证据的代码审查。审查对象是记忆，证据是 transcript，产出是 diff。没有 diff 的 dream，只是一次昂贵的总结。
