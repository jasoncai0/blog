凯一那篇《Agent 评测半年复盘》里有一句判据，我读到的时候停了一下：模型评测只定义问题，Agent 评测要同时定义解法。

今年大部分时间我在给一个设计 Agent 搭评测，四层 Rubric、两类题集、回测门禁那一套已经写成过一篇。写的时候我以为骨架齐了。读完这篇回头对，骨架里少了六根筋，其中三根是我在旧文里用「先这样，以后再说」绕过去的。

这篇不重讲 infra。只写这六处缺口是什么、我打算怎么补、每处大概几个工时。原文的观点标「原文」，我自己的判断标「推断」，没有实测的地方不编数。

## 1. 多定义的那一半是解法

模型评测里，评测者交两样东西：题和尺子。解法由训练范式内化，模型在 RL 里学会怎么答。评测集和训练集同源也不致命，因为训练要解决的问题是「在用户手里 work」。

Agent 评测多一层。prompt 里加一句「先做计划再动手」，Skill 里换一下检索顺序，上下文预算从 8k 放到 16k，这些就是解法本身。它们和题、和尺子一起决定分数，所以也得由人定义。

两重不确定性还会相乘。语言有歧义，「做得高级一点」这句指令，Agent 和我对它的理解可能不同。内部耦合又强，改第一句 prompt 会牵动第二句。

设计 Agent 里有个具体的例子。「主标题不要压住 logo」和「构图尽量居中」这两条，单独看都对，一起跑就要看谁先触发。把「多给留白」写进 prompt，排版 Skill 会把信息挪到第二屏，画布第一屏只剩一张图。这个改动在文本 Agent 里可能只影响一段话的措辞，在这里影响的是整个版面。

第三条是裁判兼选手。harness 既是被测对象，又在判分链里。原文说 Steer 到一定程度就是作弊：指标要求「搜索全面」，就往 prompt 里写「没搜到二十个结果就重试」，分数上去了，用户拿到二十条垃圾。设计 Agent 版本的作弊更容易发生，因为审美指标软。「信息层级清晰度 ≥ 0.9」这条，把副标题字号压到 11px 就能过，人看着像产品说明书。

所以抄一个 harness 抄不到解法。loop 跑起来、加终止条件、挂 Skill 和 Tool，基于任何一家 Agent SDK 封装都不难。难在业务跑起来之后：得知道里面每一处为什么这么写，改哪里会牵动哪里，改完怎么证明没坏。原文那句「每一个字符彼此之间都存在耦合」，说的是这个。

## 2. 这层会不会被模型吃掉

原文给了三条，我按自己的话转述。

1. 产品要解决最后一公里。商业上时不我待，工程改一版几小时一轮，模型迭代周期长得多；模型真强到能吃掉这层，删掉也不心疼，甚至可以卖给模型厂。
2. harness 大半工作在理解并激发模型能力。「智力」「审美」这两个词误导人，模型见过大量设计数据，能力在里面，要靠上下文和 prompt 把它叫出来。
3. harness 与 agentic RL 的训练分布共同演化。看轨迹、纠错、验证、交付，这些动作在延伸训练分布的边界。

对设计 Agent 来说，第二条最实在。模型知道「杂志感」长什么样，但它不知道这一版要的是日式极简还是编辑部浓烈。品牌包、参考图、禁用风格清单，这些是上下文里的东西，权重里没有。所以「模型变强，吼一句做得好看就行」这个预期，短期内不成立。

条件也要写清：如果厂商把某个品类做成端到端专用模型，给出品牌包接口和画布写回协议，这一层会退化成配置。这条是推断，现在没到。

## 3. 缺口一：尺子先于题目

原文最硬的一条是先定指标再定题，理由是任务不可枚举：自然语言说法无穷、低频高频混在一起、多个能力还会组合。先出题，题一定和产品目标有 gap。

我的旧文从 Task 定义开篇，等于默认维度已经在手里。实际顺序是反的：先攒了 40 道题，跑两周，发现分数不成体系，回头补维度，重写了一半题。返工两周，这时间原文没写，是我自己付的。

维度从哪来，原文给了三处：用户反馈里找共性、从别的学科借判据（Manus 的「隐喻率」借自语言学）、直接定义产品特性。第三处最被低估。产品说「给三版候选、能继续编辑」，那「可编辑性」就必须是维度。用户不会主动提这一条，提了也是「这个字我改不了」，落不到指标上。

我给设计 Agent 列的六条，每条都配了可判定命题、反指标和 owner。反指标指配在同一行、专门抓「正向分数涨了但体验变差」的那条，成对看才有约束。

| 维度 | 可判定命题 | 反指标 | owner |
| --- | --- | --- | --- |
| 品牌一致性 | 品牌色 ΔE ≤ 3，logo 安全区 ≥ 1 倍字高 | 为统一压成单色，版面没了层次 | 品牌设计 |
| 信息层级 | 主标题视觉权重 ≤ 25%，主副字号比 ≥ 1.3 | 所有元素一样大，或主标题吃掉 40% | 设计 |
| 留白节奏 | 边距 ≥ 短边 4%，元素间距是 4 的倍数 | 留白多到主体缩小，信息缺失 | 设计 |
| 图文贴合 | 文案关键词与画面主体语义一致（裁判判） | 图好看但和文案无关 | 内容 |
| 可编辑性 | 文字是文本层，图层 ≤ 40，蒙版未合并 | 为好看把文字烧进图 | 前端 |
| 改动克制 | 二次编辑只动被点名元素，其余像素差 ≤ 阈值 | 说改标题，整版重排 | 设计 |

反指标这一列不是凑数。任何一条正向指标都能被 steer，成对写才有约束：可编辑性往上走的时候，看「文字烧图率」有没有跟着涨；改动克制往上走的时候，看「该改没改率」。

## 4. 缺口二：可观测性先给人看

原文有个很反直觉的建议：极端情况下先别定指标，把结果铺出来让人看。可交互前端或截图、录屏、每步行动摘要、时间与 token、加载了哪个 Skill、跑在哪个 harness 上。观察者靠主观喜好判断，看多了，把话说清楚，维度就出来了。

我把它落成结果画廊。一屏一个任务，三版候选并排，下面挂这次运行的 op 时间线、成本、时延、用到的 Skill 版本。默认按时间倒序。

不按总分排，理由是排序是尺子的函数。尺子还不稳的时候，按分数排会把尺子不认识的问题全部藏起来，看十次也发现不了新东西。

节奏定在每周五 30 分钟，随机抽 10 条，只问一句「这条我会不会发给客户」，把原话记下来。随机，不挑最低分的那 10 条。最低分那批已经在归因队列里了，画廊要看的是分布里的中段。

一个工程要求：画廊读的是同一份 trace，不要为了它另建一套日志。两套日志一定会不一致，然后没人信。

画廊 v0 的边界是一周内能上：一个静态页、每任务三张截图、一段 op 摘要、成本与版本号。没有筛选、没有趋势图、没有权限。

连续三周一条新维度都没进账，先换看的人，再换看的任务。第一次请客户成功或销售来看，他们挑的毛病和设计师不一样；还不行就换任务类型，电商主图换成海报或落地页；第三步才是双人同看同一条，当场把分歧说开。顺序不能反，换任务是成本最高的一步。

## 5. 缺口三：判断要记账

原文说，主观判断要自己担着：敢下判断，再用实验去观测；主观定义经时间检验会变成客观标准；证不出来就上线 AB，不必继续找证据。

「敢下判断」落到日常，是一本台账。每条记录六个字段。

| 字段 | 填什么 | 例子 |
| --- | --- | --- |
| 原话 | 判断人当时怎么说的，不改写 | 「标题太抢，压住了产品」 |
| 谁判断 | 人名与角色，不写「设计团队」 | 林，品牌设计 |
| 日期 | 判断发生的日期 | 2026-11-06 |
| 反例 | 什么情况下这条不成立 | 促销海报需要标题抢，例外 |
| 验证方式 | 怎么把它变成可判定的命题 | 主标题视觉权重 ≤ 25% |
| 复核日 | 什么时候回头看这条是否被证实 | 2027-02-06 |

规则三条。每周最多入账 3 条，多了说明是在瞎判；每条必须写反例，没有反例的是口号；每条要有验证方式和复核日，否则永远停在「感觉」。

转化路径走一遍。「标题太抢」先改成可判定命题「主标题视觉权重 ≤ 25%」，再写成像素测量的判分器，进 L1 结构层，跑 150 条回归看误杀率，通过后进 `rubric_version`。一条判断从口头到进尺子，半天到两天。

台账还给我一个数：三个月内判断被验证的比例。这个比例低于一半，说明团队的审美共识还没形成，尺子加得再多也是自欺。

旧文归因的十筐里，第十筐是「改尺子」。那是一个出口，台账是入口。只有出口没有入口，尺子就只能靠拍脑袋改。

## 6. 缺口四：静态守能力，动态找维度

原文说，真实世界关联强的 Task 要两套机制：有时效信息的做快照，变成明确能力的回归；直接跑真实任务，用来提取灵感和维度。

设计 Agent 的「时效」不是新闻，是平台规格、品牌包版本、素材版权状态、字体授权。小红书的主图比例改版，同一道题的正确答案就变了，冻结的题会开始误判。这类东西必须有版本号，快照按版本取，不按日期取。

四格分开跑。

{{< fig "diagrams/04-modes.svg" "横轴是环境稳不稳，纵轴是这轮跑完要不要判通过。判通过的两格进 CI，不判分的两格进周会。" >}}

1. **冻结回归集**：每次合并前跑，题与环境都不变，只判 pass / fail，这是门禁。
2. **规格快照回归**：平台或品牌包变更后重放，带着快照版本号，判 pass / fail，用来确认改动没伤到旧能力。
3. **黄金样本画廊**：每周 10 条人看，不判分，只记判断，产出新维度。
4. **真实工单日跑**：每天 20 条脱敏工单，跑完只归档异常，不判分。

纪律只有一条：动态线不进判分流程。一旦进了，它就会被当成回归题去调参，调着调着就只会发现已经知道的问题。

动态线的指标不看通过率，看两个数：本周新增失败模式数、重复失败率。前者衡量还在不在发现新东西，后者衡量修没修干净。

成本可以算。20 条一天，单条约 ¥2，一天 ¥40，一个月约 ¥1200，比一次全量回测便宜。

## 7. 缺口五：反指标与 holdout

单一指标一定会被 steer，这不是模型坏，是指标定义不完整。原文的搜索例子说的就是这个：指标只写了「全面」，没写「相关」。

所以每条正向指标配一条反指标，成对进 Rubric。三条我实际在用的：

1. 可编辑性配「文字烧图率」。为了画面干净把文字合并进图层，判分器看不出，人一编辑就发现改不了。
2. 信息层级配「尺寸方差下限」。所有元素一样大是另一种失败，主标题不够突出和全都突出是一回事。
3. 改动克制配「该改没改率」。过度保守会让 Agent 说什么都只动一个像素，用户还是得手动重做。

holdout 是另一道闸。150 条题集里切出 30 条（20%）不进调优，只在门禁跑。这 20% 一旦被用来改 prompt，它就变成了训练集，分数会虚高。每季度换掉 1/3，换下来的进调优池。

最后一条旧文漏了：裁判不能和选手同源。生成用 A 家的多模态模型，判分最好用 B 家；只能用 A 家的时候，抽 10% 用人工或另一家交叉复核。同源同版本时，模型对自己的输出有系统性偏好，成对比较的胜率会偏高。

## 8. 缺口六：用户端不给总分

原文 5.2 讲用户视角：专业 benchmark 相对公允，但受众只看通过率和耗时，忽略 token 效率和评测维度；截图二次传播之后，「斩杀线」比结论跑得远。

我的判断是用户端不该出现总分。客户拿一个分数没有决策价值，他要么接受，要么改一句话重来。

所以对外只给三样。

1. 硬约束过没过。没过就标出位置，红框圈在画布上，配一句人话，比如「logo 离边缘太近」。
2. 与上一版的成对比较。两张并排，问「哪张更接近你要的」，不给分，也不给百分比。
3. 成本与时延。这次花了多少、等了多久，用户对这两个数最敏感。

一次通过率、Rubric 分层得分、归因分布，留在内部看板。这些数给出去只会被当成排名。

这条我没有 AB 数据，是设计判断。上线后看两个数：用户点「重新生成」的比例有没有下降，改一句话之后接受的比例有没有上升。

## 9. 先做哪五件

按投入产出排。前三件 8 个工作日内能跑起来，五件全做完约 18 个工作日。

1. **维度表**，2 天。六条维度、每条的命题、反指标、owner，写在一张表里，先让设计和前端各认领三条。
2. **结果画廊 v0**，1 周。静态页加截图加 op 摘要，先能看，再谈筛选。
3. **判断台账**，半天建表，之后每周 30 分钟。这半天是整个清单里回报最高的一笔。
4. **动态线**，2 周。每天 20 条脱敏工单，只归档异常，指标只有新增失败模式数和重复失败率。
5. **holdout 与裁判不同源**，1 天。切 20% 题集出来，改一下判分模型的调用配置。

用户端展示放最后。尺子不稳的时候改展示，改的是包装。

六处缺口里，只有第一处算设计，其余五处是记账：把判断、失败、版本记下来。这也是原文那句话的另一面，评测是系统行为的具象化，具象化靠的是记录，不是灵感。
