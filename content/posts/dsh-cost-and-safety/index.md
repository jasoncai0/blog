> 依据：DeepSeek Harness `0.2.2-rc.1`，commit `fcc0ad46`。本文是第三季的横切篇，数字来自源码常量与 `docs/`；没有做真实计费实验，成本结论是结构推导。

前 10 篇讲的是「怎么跑」。这一篇讲两件在跑起来之后才会被问的事：这一跑花了多少，以及这一跑最坏能坏到哪。

## 0. 结论

- 成本的分子是输出 token，分母是前缀复用率。前缀每变一次，整段缓存作废；压缩、时间注入、工具增删都在动前缀。
- 安全不靠单点，靠五层各自能拒绝：输入、模型、工具、沙箱、凭据。任意一层失守，其余四层仍有活路。
- 两者方向相反：省钱倾向少问人、少截断、少隔离；安全倾向多问、多留证据、多隔离。DSH 的选择是把冲突显式化，而不是藏进默认值。

## 1. 一次调用的账单

`TokenUsage` 的四个计数是互斥的，这一点常被读错：

| 字段 | 含义 | 计费口径 |
| --- | --- | --- |
| `inputTokens` | 未命中缓存的输入 | 全价 |
| `cacheReadTokens` | 命中前缀缓存的输入 | 折扣价 |
| `cacheWriteTokens` | 写入缓存的输入 | 通常高于全价 |
| `outputTokens` | 生成 token | 全价，单价最高 |

源码注释写得很直白：`billed input = inputTokens + cacheReadTokens + cacheWriteTokens`（`packages/llm/llm/src/types.ts:177-194`）。把 `cacheReadTokens` 当成 `inputTokens` 的子集，会算出双倍成本。

{{< fig "diagrams/01-cost-composition.svg" "一次请求的四个计数互斥：缓存读是折扣，缓存写是溢价，输出最贵。省钱的杠杆在复用率，不在单价。" >}}

一次请求的实际账单还包含前几次请求留下的东西：

- 系统提示词与工具 schema 每次都在，但内容是稳定的，正常应整段命中。
- 历史消息逐轮增长；只要不在中间插入新内容，旧部分一直命中。
- 工具结果、文件内容、命令输出都会进入历史，它们是一次性的，下一轮仍要按输入计费。

所以「上下文长度」不是成本，`上下文长度 × 未命中比例` 才是。

## 2. 前缀在哪里断

模型看到的请求是线性序列：系统提示词、工具 schema、历史消息、本轮输入。缓存按前缀匹配，第一个不同的 token 之后全部重算。

| 动作 | 断点位置 | 代价 |
| --- | --- | --- |
| 工具增删 | 工具 schema 段 | 整段历史重算 |
| 系统提示词文本变化 | 第一段 | 全部重算 |
| 历史中插入新消息 | 插入点 | 插入点之后重算 |
| 压缩替换旧消息 | 替换起点 | 起点之后重算 |
| 时间注入到尾部 | 尾部 | 只重算新增的几十 token |

第三季第 6 篇讲过时间注入为什么落在尾部；这里补一句成本解释：它把断点放在最末端，代价是常数级。

压缩没有这个自由。它必须删掉旧内容，断点必然落在历史中段。DSH 能做的是把「删多少」变成可计算的选择。

## 3. 压缩的盈亏平衡

压缩有两个动作，成本不同：

1. 剪枝工具结果：不调模型，只把长结果替换成头尾摘要（头 4096 字符、尾 1024 字符）。断点在第一个被剪的结果。
2. 摘要替换：调一次模型生成摘要，再把一段历史替换成一条 `user/message`。断点在替换起点。

{{< fig "diagrams/02-cache-break-even.svg" "压缩把断点前移：省下的是每轮都要付的旧历史，付出的是压缩当次的全量重算与摘要调用。" >}}

设压缩前上下文 T，压缩后 T'（T' ≈ 保留尾部 + 摘要），缓存读单价为输入价的 r（常见 0.1–0.25），压缩当次多付 (T' 的全价重算) + 摘要输出。之后每轮省 (T − T') × (1 − r)。

平衡轮数 ≈ 压缩成本 ÷ 每轮节省。T' 越小、保留越少，省得越多，但丢的上下文也越多。`compaction-basic` 的默认值把这个权衡写死了：

- `thresholdRatio = 0.8`：用到窗口 80% 才触发。
- `retainRatio = 0.16`：保留约 16% 的尾部。
- `headroomTokens = 65536`：给下一次请求留的余量。

副作用：压缩后如果任务立刻结束，这次压缩是净亏。压缩的价值随剩余轮数增长，这也是为什么它挂在 `agent/pre-step` 而不是每一步都跑。

## 4. 并发把成本乘起来

单个调用的账算清楚后，还有三个乘数：

| 机制 | 默认 | 成本影响 |
| --- | --- | --- |
| 工具批次并发 | native 执行器默认 10 | 同一 step 内多个工具并行，结果都进历史 |
| 子代理并发池 | 默认 8 | 每个子代理有自己的上下文与请求 |
| 后台 job 输出 | 结算后保留 16KB | 输出进历史时按输入计费 |

并发省的是墙钟时间，不省 token。一个 8 路委派的 turn，账单接近 8 个独立会话之和，减去共享的前缀。

DSH 没有做「预算硬上限」这种全局刹车；预算控制交给上层（Goal Round 上限、`maxParallelToolCalls`、压缩阈值）。这是一个取舍：硬上限会在长任务里误杀，软阈值把判断留给调用方。

## 5. 安全的五层边界

{{< fig "diagrams/03-five-layers.svg" "五层各自能拒绝：输入过滤、模型选择、工具策略、沙箱、凭据。每层都假设其余四层可能失守。" >}}

| 层 | 能做什么 | 典型失守 |
| --- | --- | --- |
| 输入 | 文件引用、命令解析、附件类型限制 | 间接注入：网页/文件里的指令被当作用户意图 |
| 模型 | 路由到不同能力/成本的模型 | 提示词越狱，让模型主动请求危险工具 |
| 工具 | schema 校验、`when` 准入、审批、guard | 参数合法但语义危险（`rm -rf` 也是合法参数） |
| 沙箱 | 文件/网络/进程隔离，越界升级需审批 | 沙箱配置过宽，或工具绕开沙箱直接执行 |
| 凭据 | 最小权限、按需注入、脱敏 | 子代理或 MCP server 继承了不该有的凭据 |

五层里只有工具层是「每次调用都经过」的，所以它承担了大部分显式策略；其余四层是环境约束，失守时往往没有日志。

## 6. 拒绝链的顺序

一次工具调用的拒绝链是有序的，顺序本身是设计：

{{< fig "diagrams/04-refusal-chain.svg" "先跑 pre-execute 策略，需要时问人，再跑 guards，最后才执行；deny 短路，ask 不可用等于 deny。" >}}

1. `tools/pre-execute` waterfall：hooks、权限策略、沙箱检查。可以返回 `allow`、`deny`、`cancel`、`ask`。
2. `ask` 走 `ctx.approval.request`：没有审批通道、没有 agent 可路由，结果都是 deny。用户拒绝也是 deny。
3. `guards`：只在允许的调用上运行，单调返回第一个拒绝理由。
4. 执行工具本体。

审批在 guards 之前，这个顺序容易被读反。原因是 guards 的语义是「已授权的调用是否还违反不变量」，它需要看到确定的调用；如果先跑 guards，用户可能为一个注定被拒的调用被打扰。

## 7. 一次越界的完整路径

一个典型场景：模型要执行 `curl http://169.254.169.254/latest/meta-data/`。

1. 工具层 schema 通过，命令字符串合法。
2. `tools/pre-execute` 的沙箱策略识别内网地址，返回 deny 或 ask。
3. 若 ask：没有审批通道时直接 deny，模型看到 `Error: ... requires approval, but no approval channel is available`。
4. 若放行：沙箱在 spawn 时限制网络，命令失败，错误作为 `tool/result` 回到模型。
5. 凭据层：即使命令成功，实例元数据里的令牌也不该在环境变量里。

这条路径说明一件事：安全不是一个开关，是五次独立的拒绝机会。任何一次有效，攻击就不成立。

## 8. 设计取舍

| 取舍 | 选择 | 代价 |
| --- | --- | --- |
| 预算控制 | 软阈值 + 上层策略 | 调用方要自己设上限 |
| 压缩时机 | 压力触发，不按步 | 压缩后立即结束会亏 |
| 审批位置 | guards 之前 | 可能为最终被拒的调用打扰用户 |
| 沙箱默认 | 工作区写，越界需批准 | 频繁越界的任务体验差 |
| 凭据注入 | 按需、最小权限 | 跨工具复用时要重复授权 |

## 9. 踩坑点

1. 把 `cacheReadTokens` 加进 `inputTokens`，成本翻倍。四个计数互斥。
2. 以为压缩一定省钱。压缩后只剩一两轮时是净亏。
3. 在系统提示词里放时间戳。每轮都变，整段缓存作废。
4. 用工具结果当「临时存储」。它每轮都按输入计费。
5. 以为 guard 能替代审批。guard 看不到用户意图，只能拒绝。
6. 以为审批能替代沙箱。用户批准的是这一次调用，不是任意后续命令。
7. 给子代理继承全部凭据。委派深度每加一层，暴露面翻倍。
8. 把 `maxParallelToolCalls` 调大当作提速手段。墙钟变短，账单变长。

## 最后

成本和安全都在问同一个问题：这次调用值不值。成本问的是「花掉的 token 换回了什么」，安全问的是「最坏情况下损失有多大」。DSH 把两者都拆成可逐层检查的常量与顺序，而不是留给一句「注意安全」。
