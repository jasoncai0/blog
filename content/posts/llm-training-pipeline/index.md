**这篇文档在做什么：** 把「预训练 / 训练 / 后训练 / 微调」这四个天天被混用的词放回同一条流水线上，先确定它们各自的层级——哪个是总称、哪两个是先后阶段、哪个根本不是一个阶段；再逐段拆开：每一段用什么数据、烧多少算力、产出什么；最后落到工程上真正会纠结的问题：SFT、LoRA、RLHF 这三个经常被摆在一起比较的东西，其实不在同一个维度上，那到底该怎么选。

如果你已经能背「预训练学知识、后训练学对齐、微调学风格」这三句话，这篇补的是它们背后的机制和代价：为什么基座模型明明什么都读过，却不会回答问题；为什么 SFT 之后还要再做偏好优化；为什么微调改不动知识、只能改行为；以及为什么「用 LoRA 做 SFT」和「用全参做 RLHF」这两句话都成立，而「SFT 和 LoRA 二选一」不成立。

## 一、四个词不在同一层

最常见的混淆，是把四个词当成四个并列的选项。它们不是。

- **训练（training）** 是总称，指一切通过梯度更新参数的过程。它下面有很多种训练，预训练和后训练是其中最大的两段。
- **预训练（pre-training）** 和 **后训练（post-training）** 是训练的两个先后阶段，在时间上串行，在目的上互补。
- **微调（fine-tuning）** 不是一个阶段，而是一类方法：在已经训练好的权重上继续训练。它可以发生在任意阶段之后。

{{< fig "diagrams/01-layers.svg" "层级关系：训练是总称，预训练与后训练是先后两个阶段；微调是正交的手段，可以叠加在任一步之后，与流水线唯一的交集是 SFT。" >}}

三条关系要分开记，混在一起就会绕：

1. **时序上**：语料 → 预训练 → 后训练 → 部署。后训练依赖预训练的产物，顺序不能颠倒。
2. **集合上**：训练 ⊃ 预训练、后训练。预训练和后训练是互斥的两个阶段，一个模型不可能「既在预训练又在后训练」。
3. **正交上**：微调是手段，不是阶段。它和上面两个阶段是乘法关系——你可以在后训练里做微调（SFT 就是），也可以在部署之后做微调（领域适配），还可以用微调的方式去做预训练（继续预训练 CPT）。

所以「微调」和「后训练」的交集只有一块：SFT。SFT 既是后训练的一个环节，也是微调的一种用法。而 RLHF 是后训练但不属于微调，客户侧的 LoRA 是微调但不属于后训练。看清这一点，后面所有的选型问题都会简单很多。

口语里还有一层错位，值得单独列出来：

| 口语说法 | 严格含义 | 容易误伤的地方 |
| --- | --- | --- |
| 「这个模型训练了三个月」 | 通常指预训练 | 把训练等同于预训练，忽略后训练 |
| 「微调一下就好了」 | 可能是 SFT、LoRA，也可能是继续预训练 | 三者成本差两个数量级 |
| 「后训练就是 RLHF」 | 后训练还包括 SFT、拒绝采样、蒸馏、安全对齐 | RLHF 只是最后一段 |
| 「训练和微调有什么区别」 | 微调是训练的子集 | 把父子关系说成并列关系 |

把四个词放回时间轴，每一站的输入输出和成本占比大概是这样：

{{< fig "diagrams/02-pipeline.svg" "五站流水线：语料 → 预训练 →（中期训练）→ 后训练 → 业务微调。算力是漏斗（约 90 / 8 / 2），能力是叠加（底座 → 可用性 → 专用性）。" >}}

下面把每一段拆开。

## 二、预训练：把知识压进参数

预训练做的事情，用一句话说就是：**给模型看足够多的文本，让它学会「下一个 token 该是什么」。**

- **数据**：万亿级 token，网页、代码、书籍、论文、多语料，**没有人工标注**。
- **目标**：自监督。GPT 这一系是自回归的 next-token prediction，BERT 那一系是掩码还原。共同点是标签来自数据本身，不需要人写。
- **算力**：万卡级，占整个流程 90% 以上。
- **产物**：Base Model，也就是基座模型。

基座模型的能力边界很特殊：它什么都读过，但只会「续写」。你问它「中国首都是哪」，它不会回答「北京」，而是倾向于续写出「中国首都是哪座城市？北京……」这种像考题一样的文本——因为在训练语料里，这句话后面跟着的往往是题目而不是答案。

这不是模型笨，是目标函数决定的。next-token prediction 优化的是「给定前文的条件下，下一个 token 的分布」，它学到的是一整套语言的统计结构，而不是「问—答」这种特定的交互格式。**知识在这一步注入，但「怎么用知识」还没教。**

顺带澄清一个常见误解：预训练不是把知识库塞进模型。它学到的是分布，不是条目。这带来两个后果——好的一面是它能泛化到没见过的组合；坏的一面是它会在分布稀疏的地方一本正经地编，而且编得很像真的。幻觉的根源在这里，不在后训练。

### 2.1 中期训练：被忽略的一段

严格的时间轴上，预训练和后训练之间还有一段，工业界叫 **mid-training**（中期训练），也有人把它算作预训练的尾段。

典型内容：

- **长上下文扩展**：在预训练末尾用长文档继续训，把上下文窗口从 8K 拉到 128K 甚至更长。
- **退火（annealing）**：最后一段把学习率降到很低，同时把高质量数据（教科书、代码、精选问答）的比例调高。

这一段的目标函数仍然是自监督的 next-token，所以性质上属于预训练，只是数据配比和学习率策略变了。把它单独拎出来的原因是：**同样的算力，花在退火阶段的效果远好于花在中段**，所以各家都会在最后一段精打细算。

## 三、后训练：从「会写」到「会用」

预训练结束后，模型的输出分布是「互联网文本的分布」，而不是「有帮助的回答的分布」。后训练要做的，就是把前者改造为后者。

后训练由四件事组成，顺序通常是从上到下：

1. **SFT（监督微调）**：用几万到几百万条高质量的 `(指令, 回答)` 对做监督学习。它教的是格式、语气、任务拆解方式，以及「被问到时应该回答而不是续写」这件事。
2. **偏好优化**：RLHF（PPO）、DPO、KTO 等。用「A 比 B 好」的比较数据，让模型输出更符合人类偏好。
3. **可验证奖励的强化学习（RLVR）**：数学、代码这类有客观对错的任务，用规则或单元测试当 reward。o1、R1 这一代推理模型的能力提升主要来自这里。
4. **安全对齐**：拒答有害请求、减少幻觉、价值观校准。

四件事的数据量比预训练小两三个数量级，但**数据配比和质量才是各家真正的 know-how**。同样 10 万条 SFT 数据，换一套筛选和配比，效果能差出一档。

为什么 SFT 之后还要做偏好优化？因为 SFT 的监督信号是「正向示范」——它只说「应该这样」，不说「那样为什么不行」。这带来两个天花板：

- 模仿的上限是示范的质量。示范里有 5% 的瑕疵，模型会照着学。
- 无法表达「比示范更好」。如果两个回答都对但一个好得多，SFT 只会把它们当成两个独立的正确答案。

偏好数据是成对出现的（chosen / rejected），提供的是**相对信号**，能表达 SFT 表达不了的东西：啰嗦 vs 简洁、谄媚 vs 直说、含糊 vs 精确。这也是为什么顺序不能反——reward model 是在 SFT 之后的模型上训的，基座太差，偏好信号会被噪声淹没。

## 四、微调：一种手段，不是一段旅程

微调的定义很短：**在已有权重上，用特定数据继续做梯度更新。** 它是一个动作，不是流水线上的一站。

按更新的参数范围，分成两类：

- **全参微调（Full FT）**：所有参数都更新。效果上限最高，显存最贵，也最容易灾难性遗忘。
- **参数高效微调（PEFT）**：冻结原权重，只训一小部分新增参数。代表是 LoRA / QLoRA，此外还有 Adapter、Prefix Tuning、Prompt Tuning。

LoRA 值得单独看一眼，因为它是绝大多数业务真正会用到的那一种：

{{< fig "diagrams/03-lora.svg" "LoRA 并联一条低秩通路：冻结 W，只学 ΔW = BA，可训练参数从 100% 降到千分之几；代价是容量有限，改不动表征。" >}}

它的做法是冻结原权重 `W`，在旁边并联两个小矩阵 `A(r×d)` 和 `B(d×r)`，前向变成 `h = Wx + (α/r)·BAx`。`r` 通常取 8 / 16 / 32，远小于 `d`（常见 4096），所以新增参数量是 `2·r·d` 而不是 `d²`。以 7B 模型为例，全参微调要 56 GB 级别的显存，LoRA 只要零点几 GB。

关于微调，最重要的一条认知是它**能改什么、不能改什么**：

| 微调擅长 | 微调不擅长 |
| --- | --- |
| 输出格式、字段结构、JSON schema | 注入大量新知识（公司文档、产品手册） |
| 说话风格、领域话术、客服语气 | 大幅改变模型的推理能力 |
| 工具调用的参数拼装 | 覆盖预训练里已经形成的强先验 |
| 特定任务的输入输出映射 | 时效性信息（今天的日期、当前库存） |

想把内部文档灌进模型，正确顺序是 RAG 优先，其次才是继续预训练；微调排在最后，而且通常只用来教「怎么引用检索结果」，不是用来存知识。这个判断能省掉大量无效实验。

还有一个归类问题常被问：**继续预训练（CPT / DAPT）算预训练还是微调？** 答案是看数据形态和目标函数，不看名字。大规模无标注语料 + 自监督目标，性质上是预训练；有标注的任务数据 + 监督目标，性质上是微调。名字只是历史包袱。

## 五、SFT、LoRA、RLHF：三个词能不能放一起比

不能直接比。这三个词分属两个维度：

- **SFT 和 RLHF** 回答「用什么数据、优化什么目标」，是**训练范式**。
- **LoRA** 回答「更新多少参数、怎么省显存」，是**参数更新方式**。

它们之间是乘法关系，不是加法关系。所以真实世界里的话应该这么说：用 LoRA 做 SFT、用全参做 RLHF、用 QLoRA 做 DPO。

把两个维度摊开，是这样一张表：

| 维度 | SFT（监督微调） | RLHF（偏好优化） | LoRA（低秩适配） |
| --- | --- | --- | --- |
| 本质 | 训练范式：监督学习 | 训练范式：偏好/奖励优化 | 参数更新技术（PEFT） |
| 数据形态 | `(prompt, 优质回答)` 成对示范 | `(prompt, chosen, rejected)` 偏好对，或 reward model | 不决定数据，取决于挂什么目标 |
| 监督信号 | 正向示范，只说「应该这样」 | 相对比较，能表达「A 比 B 好」 | 无（跟随宿主目标） |
| 损失函数 | 交叉熵 / token-level MLE | PPO 策略梯度 + KL 惩罚；DPO 用偏好对比损失 | 无独立损失，仍是宿主目标的损失 |
| 更新参数 | 全参（或 PEFT） | 全参（策略模型，PPO 另需 value/critic） | 冻结 W，只训 ΔW = BA，r ≪ d |
| 可训练参数 | 100% | 100%，PPO 需多个模型同时驻留 | 约 0.1%~1% |
| 显存门槛 | 7B 全参约 8×80G | 最高 | 单卡 24G 可跑 7B（QLoRA 更低） |
| 训练稳定性 | 高，收敛可预期 | 低，对超参和 KL 系数敏感，易 reward hacking | 高，但 r / alpha / target_modules 要调 |
| 效果上限 | 中，受限于示范质量 | 高，能超越示范水平 | 略低于全参，复杂任务差距明显 |
| 成本 | 中低 | 高（标注贵 + 算力贵 + 调参贵） | 最低 |
| 典型产物 | Chat Model 的第一阶段 | 最终对齐版模型 | 几十到几百 MB 的 adapter 文件 |

换成矩阵看更直观——纵轴选数据范式，横轴选更新方式，四格都能落地：

{{< fig "diagrams/04-axes.svg" "两轴独立：纵轴是数据范式（SFT 或偏好优化），横轴是参数更新方式（全参或 LoRA）。换纵轴不改显存，换横轴不改损失函数。" >}}

几组实战里最常见的搭配：

| 组合 | 说明 | 适用 |
| --- | --- | --- |
| **LoRA + SFT** | 性价比最高，业务落地的默认答案 | 绝大多数企业微调需求 |
| 全参 + SFT | 效果上限更高，吃显存，易遗忘 | 有数据有卡、要一次到位 |
| 全参 + RLHF | 标准对齐流水线，PPO 显存压力最大 | 做通用 Chat 模型 |
| **QLoRA + DPO** | 单卡也能做偏好对齐，比 PPO 稳 | 资源受限的团队 |
| LoRA + RLVR | 小规模复现推理能力提升 | 数学/代码场景 |

## 六、怎么选：先问三个问题

顺序很重要，问错了会白烧钱。

**第一个问题：你要模型「知道」还是「会做」？**

要注入新知识（内部文档、产品参数、时效信息），先别训——RAG 的成本低两个数量级，更新也更灵活。只有当知识必须在参数里（离线部署、极低延迟、需要模型内化风格）才考虑继续预训练。

**第二个问题：你手上是「示范」还是「比较」？**

能写出标准答案，就用 SFT，这是最短路径。说不清标准答案、但能判断两个谁更好，才轮到偏好优化。有客观对错（数学、代码、结构化抽取）且能自动判分，用 RLVR 比 RLHF 便宜得多也稳得多。

**第三个问题：显存够不够？**

不够就走 LoRA / QLoRA。它不改变前面两个问题的答案，只改变实现方式。

{{< fig "diagrams/05-cost.svg" "成本与效果上限的分布：从 prompt 到 PPO，成本逐级上升，效果上限也逐级上升，但边际收益递减。" >}}

具体到「什么时候选哪个」：

**选 SFT，当：**

- 你手上是好的示范，没有成对的比较数据
- 目标是格式、风格、话术、工具调用（强制 JSON、客服语气、function call 结构）
- 领域任务明确，输入输出形态固定（分类、抽取、改写）
- 数据量 1k ~ 100k 条，质量可控

**选偏好优化（DPO / RLHF），当：**

- 说不清标准答案长什么样，但能判断哪个更好
- 要压制坏习惯：啰嗦、谄媚、过度拒答、幻觉
- 有可验证的 reward（答案对错、单测通过），想把推理能力再提一档
- 已经有一个可用的 SFT 模型，想在此基础上再提升

**选 LoRA，当：**

- 显存不够，单卡 24G/48G 想微调 7B/13B
- 需要多套定制共存：一个基座 + N 个 adapter，按租户或任务热插拔
- 快速迭代试错，一天要跑十几个实验
- 不想破坏基座模型的通用能力

**三个都先别选，当：**

- 要注入大量新知识 → 先上 RAG，其次继续预训练
- 数据少于 500 条 → 先做 prompt engineering 和 few-shot，训了大概率过拟合
- 只是想让模型知道当下信息（日期、库存、用户资料）→ 放进上下文就行

## 七、几个高频误区

1. **「SFT、LoRA、RLHF 三选一」**：把正交维度并列了。正确的说法是「用 LoRA 做 SFT」还是「用全参做 RLHF」。
2. **「DPO 是 RL」**：严格说 DPO 是偏好优化，用分类式的对比损失直接拟合偏好，没有策略梯度，也不在线采样；但工程上通常归入「RLHF 类」一起讨论。
3. **「跳过 SFT 直接 RLHF」**：reward model 在烂模型上训不准，对齐会崩。标准顺序永远是 SFT → 偏好优化。
4. **「SFT 不会遗忘」**：全参 SFT 最容易丢通用能力。混入 5%~10% 的通用数据能显著缓解；LoRA 天然更抗遗忘，因为原权重没动。
5. **「LoRA 只是省显存」**：它还带来可插拔和多任务共存，这是全参微调给不了的。但反过来，需要大幅改变表征或注入领域知识时，LoRA 明显不如全参，别硬上。
6. **「数据越多越好」**：1k 条精标 SFT 经常胜过 100k 条爬取数据。偏好标注的一致性比规模更关键——标注员自己都摇摆的数据，训不出稳定的偏好。

## 八、四句话收尾

- **训练**是总称，**预训练**和**后训练**是它的两个先后阶段。
- **预训练**给能力底座（知识 + 语言），成本占九成，产物是只会续写的 Base Model。
- **后训练**给可用性和对齐（SFT → 偏好优化 → RLVR → 安全），产物是 Chat Model。
- **微调**是手段不是阶段：它可以是后训练里的 SFT，也可以是部署后的领域适配；决定它效果的是「能不能改得动」，不是「训了多少步」。
