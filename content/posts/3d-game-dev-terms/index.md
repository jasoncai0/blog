> 这四个词分属四个层次。Blender 是建模工具，白模是关卡没做完时的灰盒版本，管线是资产从软件流进游戏的那条路，蓝图是虚幻引擎里的可视化脚本系统。觉得难懂，多半是有人把工具、产物、流程和系统放在一句话里比较。

## 0. 四类名词，先分开再记

| 类别 | 例子 | 回答的问题 |
|---|---|---|
| 工具 | Blender、Maya、Substance Painter、Unreal、Unity | 用什么做 |
| 产物 | 白模、模型、贴图、材质、动画片段、关卡 | 做出来的是什么 |
| 流程 | 资产管线、导出、烘焙、打包、版本控制 | 从 A 到 B 怎么走 |
| 系统 | 蓝图、动画状态机、渲染管线、物理 | 运行时按什么规则跑 |

同一句话里混进两类，理解就会卡住。「Blender 的蓝图怎么导出」这句不成立，因为蓝图不在 Blender 里，它是引擎里的资产。

「管线」是唯一的例外，它同时落在流程和系统两栏：资产管线、构建管线是流程，渲染管线是系统。单说「管线」归不了类，得看前面的定语。

## 1. 管线：一条资产路径，三套说法

「管线」在游戏公司至少指三件事。

1. 资产管线：模型、贴图、动画从 DCC 软件进引擎，再进包体的流程。
2. 渲染管线：GPU 在一帧里做顶点变换、光栅化、着色、后处理。
3. 构建管线：CI 上编译、烘焙、打包、上传的自动化流程。

日常对话里的「管线」多数指第一种。有人问「你熟悉管线吗」，先确认是哪一种，答错方向会被追问到没词。

资产管线的五个阶段：

| 阶段 | 输入 | 输出 | 谁负责 |
|---|---|---|---|
| 建模与展 UV | 参考图、白模 | `.blend` | 3D 美术 |
| 导出 | `.blend` | `.fbx` / `.gltf` / `.usd` | 美术或 TA |
| 导入 | 模型 + 贴图 | `.uasset` / `.prefab` | 引擎，TA 配规则 |
| 组装 | 资产 | `.umap` / `.unity` 场景 | 关卡策划 |
| 打包 | 场景 + 资产 | `.pak` / `.utoc` + `.ucas`、apk/ipa | 构建机 |

中间格式的作用是解耦。`.blend` 只有 Blender 认，引擎不读；FBX 这类格式带网格、UV、骨骼、动画和材质名，程序化修改器、节点材质、约束留在源文件里。导入不是复制文件，是重建资产：引擎里存的是另一份数据，源文件改了要重新导出、重新导入。

{{< fig "diagrams/01-pipeline.svg" "一条资产从 .blend 到安装包经过五个环节；白模和贴图从另外两条路进入管线" >}}

管线里最贵的一步通常是返工。命名规则、单位、坐标轴、UV 通道这些约定在项目第一周定下来，后面每改一次模型能少一轮沟通。返工的代价按阶段跳：改白模是分钟，改贴图是小时，改已经组装好的关卡和光照是天。

## 2. Blender：DCC 工具里的一个

DCC（Digital Content Creation）指建模、雕刻、贴图、动画这类内容生产软件。Blender、Maya、3ds Max、Cinema 4D、ZBrush、Substance Painter 都算。Blender 免费开源，[当前版本 5.3](https://www.blender.org/download/)，独立开发者和中小团队用得多。大厂管线里常见 Maya 做主模型、3ds Max 做场景、ZBrush 做高模，Blender 做补充或个人项目。

Blender 在管线里负责四段：建模和拓扑、展 UV、绑定与动画、渲染静帧和过场。它不管运行时逻辑、物理、打包和平台适配，这些归引擎。

导出时容易踩的三个坑：

1. 单位不一致。Blender 默认 1 单位是 1 米，UE 内部按厘米，Unity 按米。导出 FBX 时确认 Apply Unit 和缩放，不然 1.8 米的角色进 UE 可能只有 1.8 厘米。
2. 坐标轴不一致。Blender 的 Z 朝上，引擎通常是 Y 朝上。导出设置里选对 Up Axis，模型和动画才不会躺倒。
3. 修改器没应用。细分、镜像、阵列这些修改器默认不写进导出结果，导出前 Apply，或者确认导出器勾了应用修改器。

`.blend` 文件可以打包贴图（Pack Resources），传给同事时不会丢外部图片。引擎不认这个格式，它只是源文件。

## 3. 白模：关卡的可玩性草稿

白模（whitebox，也叫灰盒 greybox、粗搭 blockout）是用灰白几何体、胶囊体和简单盒子搭出来的关卡版本。它只验证空间和玩法，不带贴图、光照、特效、道具细节。

先做白模的理由是改错成本。关卡的尺寸、掩体位置、视距、跳跃距离、敌人从哪进来，这些决定好不好玩；等美术做完再改结构，要重做模型、UV、碰撞和光照。白模阶段挪一个盒子只要几秒。

白模通常在引擎里直接搭，用基础几何体加碰撞，不经过 Blender。作者是关卡策划（level designer）。相关词有几个：blockout 指粗搭阶段，greybox 强调灰盒材质，proxy mesh 指代替成品的低模（也用于碰撞和远景），kitbash 指拿现成模块件拼场景，set dressing 指往场景里摆道具、做磨损和生活痕迹。

{{< fig "diagrams/02-whitebox.svg" "同一个俯视布局：白模只放盒子，成品补上贴图、光照和道具，几何与动线在两版里保持一致" >}}

「灰盒测试」是 QA 的词，指功能没做完时的可测版本，和白模不是一回事。

## 4. 蓝图：虚幻引擎的可视化脚本

Blueprint 是 Unreal Engine 的节点式脚本系统，落到项目里，每个蓝图类又是一份二进制资产。策划和美术连节点写玩法，编译后由蓝图虚拟机逐节点执行。它解决的是「改一个数值、加一个开关要不要等程序员」的问题。

UE 里的节点图不止一种，叫蓝图的只有一类：蓝图类（Actor、Character、GameMode 等）、关卡蓝图（管当前关卡的全局事件）、动画蓝图（每帧算骨骼姿态）、控件蓝图（UI）。材质编辑器也是节点图，但它是着色器，不是蓝图。

和 C++ 的分工按执行频率和数量划：底层系统、频繁调用的数学、网络同步用 C++；玩法胶水、关卡事件、UI 流程用蓝图。经验线是：一个 Tick 里几十个对象的小逻辑，蓝图够用；上千个 Actor 每帧跑，或单帧几百次向量运算，搬去 C++，因为 VM 每个节点都要分发一次。UE5 已经[移除蓝图 nativization](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/Engine/UBlueprint/NativizationFlag)，热路径只能手写 C++，或者挪到 Niagara、材质、GPU 侧。

蓝图的协作代价在版本控制。它是二进制资产，diff 不可读，两个人改同一个蓝图只能排队。大团队的做法是 C++ 定义接口和数据结构，蓝图只做配置和拼装。

Unity 的对应物是 Visual Scripting（原 Bolt）；Godot 4 移除了 VisualScript，常用 GDScript 或 C#。所以「蓝图」这个词基本只在 UE 语境里成立。

## 5. 材质与贴图：PBR 把光照留给引擎

先理一条术语链：网格（mesh）决定形状，UV 决定贴图怎么铺，贴图（texture）是像素数据，材质（material）是贴图加参数的组合，着色器（shader）是算颜色的一段程序。

PBR（Physically Based Rendering）的核心约定是贴图里不画光照，光照由引擎按灯光、法线、粗糙度实时算。五张核心图，外加一张可选的高度图：

| 贴图 | 存什么 | 常见坑 |
|---|---|---|
| BaseColor / Albedo | 表面本色，不含阴影和高光 | 画了阴影会双重变暗；颜色图按 sRGB 导入 |
| Normal | 每个像素的表面朝向 | OpenGL 与 DirectX 的绿通道相反，反了凹凸会倒 |
| Roughness | 粗糙度，越白越粗糙 | 有的软件存光滑度，数值要取反 |
| Metallic | 金属度，通常 0 或 1 | 中间值只用于金属与锈蚀的过渡 |
| Ambient Occlusion | 缝隙处的间接光衰减 | 别把它烘进 BaseColor |
| Height | 高度，做视差或位移 | 视差只改采样，模型轮廓不变 |

{{< fig "diagrams/03-pbr.svg" "一张 PBR 材质由五张图组成，各管一件事；着色器每帧把图和灯光合成最终颜色" >}}

通道打包能省采样和显存。UE 把 AO、粗糙度、金属度压进一张 ORM 的 R/G/B 通道；Unity HDRP 用 [Mask Map](https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@17.4/manual/Mask-Map-and-Detail-Map.html)，R 金属度、G AO、A 光滑度。看清楚项目用哪套，贴图通道别接错。

纹理压缩按平台选：PC 常用 BC7，移动端用 ASTC 或 ETC2，尺寸常见 2048。同一场景的 texel density（每米多少像素）要接近，否则近处糊、远处反而锐。材质和贴图的区别一句话：贴图是输入，材质是「用哪些贴图、参数怎么调」的资产。

材质接错时的排查顺序：发灰，先看 BaseColor 是否按 sRGB 导入、Normal 的绿通道方向对不对；过亮，先看 BaseColor 里有没有画光照、Roughness 是不是把光滑度接反了。

## 6. 骨骼、蒙皮与动画状态机

骨骼（skeleton）是一组带层级的关节。蒙皮（skinning）把模型顶点绑到关节上，一个顶点常见受 4 根骨骼影响（引擎可配到 8 根），权重之和为 1。绑定（rigging）是建骨架、刷权重、加控制器的全过程。

动画片段（clip）是一个动作的数据。引擎播放动画要回答两个问题：现在播哪个动作，动作之间怎么过渡。

1. 状态机（state machine）回答第一个：Idle、Move、Jump、Land、Hit 这些状态按条件切换。
2. 混合空间（blend space）回答第二个：速度从 0 到 600 时，Walk 和 Run 按比例混合，不切成两个独立状态。
3. 根运动（root motion）决定位移由谁给：动画里的位移驱动角色，还是代码按速度移动、动画只做腿部循环。
4. IK（反向运动学）让脚落在斜坡和不平地面上；FK 是正向运动学，逐级旋转关节。
5. 重定向（retarget）把同一套动画套到不同体型；morph target（shape key）做表情和口型。

{{< fig "diagrams/04-anim-state.svg" "状态机管播哪段，混合空间管同一段里怎么混；橙色虚线表示任意状态都能触发的转移" >}}

这些规则组合起来就是动画蓝图：每帧读速度、是否在空中、是否受伤，输出姿态。做写实体育或格斗项目还会用到 motion matching，它按当前速度和输入从动作库里检索最像的一帧，替代手工状态机的大部分工作。

## 7. 引擎运行时：对象、光照、性能

对象模型有两套常见说法。UE 用 Actor（能放进关卡的对象）和 Component（挂在 Actor 上的功能块），关卡是 Level，世界是 World。Unity 用 GameObject、Component、Prefab（可复用的对象模板）、Scene。

Tick / Update 是每帧调用的更新函数。能事件驱动就别放 Tick，几百个对象每帧空跑也会吃 CPU。

碰撞体和渲染网格分开：渲染用高模，碰撞用盒子、胶囊或凸包。碰撞通道（channel）决定谁和谁碰，子弹打墙和角色走路用的通道通常不同。

光照分两条路：静态光照烘焙（bake）把光照算进 lightmap，运行时便宜，改灯要重烘；动态全局光照（UE 的 Lumen、Unity 的实时 GI）不用等烘焙，代价是 GPU。烘焙也用来把高模细节算进法线贴图，两个「烘焙」语境不同。

Nanite 是虚拟几何，按屏幕像素自动选细节层级，适合高模静态场景；半透明、程序化变形和部分骨骼网格还要走传统 LOD 或专门方案。LOD 是同一模型的多级网格，远了换低模；HLOD 把一片远景合成一个代理；剔除分视锥剔除和遮挡剔除；开放世界用流送（streaming）按距离加载。

性能看几个数：draw call、三角形数、显存、每帧预算。60 fps 的预算是 16.7 ms，30 fps 是 33.3 ms，渲染、逻辑、物理、音频都要在这段里分。1% low 比平均帧率更能说明卡顿。

## 8. 团队、阶段与协作词

GDD（Game Design Document）写玩法、系统、关卡和数值；TDD（Technical Design Document）写技术方案和风险。垂直切片（vertical slice）是一段能完整玩通的小样，用来证明这个游戏好玩，通常在立项后几个月内做出来。

阶段词按顺序：原型验证核心玩法，垂直切片验证品质和管线，Alpha 内容基本齐，Beta 全流程可玩、开始调优，Gold 进厂压盘或提交平台认证（cert），上线后进入 live ops。

岗位缩写：策划分系统、关卡、数值、剧情；3D 美术分角色、场景、地编；TA（技术美术）管管线和工具；另有客户端程序、引擎程序、QA、音频、制作人。

音频中间件 Wwise、FMOD 负责混音、总线和互动音乐；本地化（l10n）管文本、字体、配音和区域合规。版本控制因为二进制资产多，常用 Perforce；用 Git 要配 LFS，否则 `.psd`、`.fbx` 很快把仓库撑爆。

## 9. 八组容易混的词

| 词 | 容易被当成 | 实际指 |
|---|---|---|
| 白模 | 还没上材质的半成品 | 验证关卡用的灰盒，可能永远不进最终包体 |
| 灰盒测试 | 白模 | QA 在功能未完成时的可测版本 |
| 蓝图 | 建筑设计图 | UE 的可视化脚本资产 |
| 管线 | 渲染管线 | 多数时候指资产管线，先问上下文 |
| 烘焙 | 打包压缩 | 把光照或法线细节算进贴图 |
| LOD | 画质档位 | 同一模型的低细节版本 |
| 蒙皮 | 皮肤材质 | 顶点绑骨骼的权重 |
| 打包 | zip 压缩 | 生成平台能直接运行的包体 |

## 10. 上手顺序

1. 建模和 UV（约两周）：在 Blender 建一个房间，展 UV，导出 FBX。
2. 引擎导入（约一天）：导进 UE 或 Unity，检查单位和缩放，摆进关卡。
3. 蓝图或脚本（约两周）：做一个能开门、能拾取的交互。
4. 材质与光照（约一周）：给房间上 PBR 材质，打一盏灯，看阴影落在哪里。
5. 动画与打包（约一周）：导入一段走路动画，接状态机，打一个能运行的包。

走完这五步，术语表里的词会各自落到一个你摸过的位置。下一步是打开 Blender 建一个两米高的盒子，导出，再导进引擎看它到底多大。
